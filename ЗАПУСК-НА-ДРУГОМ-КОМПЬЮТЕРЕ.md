# Как перенести и запустить RealEstate Analytics

Инструкция рассчитана прежде всего на Windows. Основной вариант — Docker с PostgreSQL. Для Windows также описан запуск без Docker с SQLite, как на текущем компьютере.

## 1. Что перенести

Скопируйте папку проекта `Nedvichka` на другой компьютер, например в `C:\Projects\Nedvichka`.

В копии должны остаться:

- папки `backend`, `frontend`, `sample-data`;
- `docker-compose.yml`, `.env.example`, README и эта инструкция;
- обязательно `frontend/package-lock.json` и файлы миграций `backend/alembic`.

Можно не копировать `.venv`, `frontend/node_modules`, `frontend/.npm-cache`, `frontend/dist`, `tmp`, `__pycache__` и `.pytest_cache`. Они создаются заново. Виртуальное окружение `.venv` нельзя считать переносимым: на новом компьютере создайте его заново.

**Если нужны нынешние аккаунты, объявления и история:** после остановки приложения сохраните `backend/realestate.db`. На текущем компьютере использовалась именно эта SQLite-база. Для продолжения с ней выберите вариант без Docker из раздела 3. Этот файл содержит данные пользователей, включая хеши паролей; передавайте копию только тем, кому разрешён доступ к базе.

Docker использует отдельную PostgreSQL-базу в томе. Копирование `realestate.db` не загружает её в PostgreSQL. Без отдельного переноса данных Docker начнёт с новой пустой базы. Импорт CSV/XLSX переносит предложения, но не аккаунты и историю оценок.

## 2. Вариант A: Docker + PostgreSQL

### Подготовка

Установите Docker Desktop, включите Linux-контейнеры и запустите Docker Desktop. Если установка требует WSL 2 или перезагрузку, завершите эти шаги. На Linux нужен Docker Engine с Compose. Отдельно устанавливать Python, Node.js и PostgreSQL для этого варианта не требуется.

Откройте PowerShell в папке проекта. Команды ниже выполняются из корня, где лежит `docker-compose.yml`:

```powershell
cd C:\Projects\Nedvichka
docker --version
docker compose version
```

При первом запуске нужен интернет для загрузки образов и зависимостей.

### Настройка администратора

Если `.env` ещё нет, создайте его:

```powershell
Copy-Item .env.example .env
notepad .env
```

Укажите собственные значения `ADMIN_EMAIL` и `ADMIN_PASSWORD`. Email должен быть корректным, пароль — минимум 12 символов. Используйте новый email, который ещё не зарегистрирован обычным пользователем. Предустановленного административного аккаунта нет.

`JWT_SECRET` можно оставить пустым: сервер сам создаст случайный секрет и сохранит его в Docker-томе. Либо задайте собственную случайную строку минимум из 32 символов. При изменении JWT-секрета потребуется войти заново.

Реквизиты `POSTGRES_*` меняйте до первого запуска базы. Для пароля PostgreSQL используйте длинную случайную строку из латинских букв и цифр, чтобы избежать проблем со специальными символами в URL подключения. Сохраните `.env`, не публикуйте его.

### Запуск

```powershell
docker compose up -d --build
docker compose ps
docker compose logs --tail=80 backend
```

Первый запуск может занять несколько минут. Backend автоматически применяет миграции и создаёт администратора из `.env`.

Откройте в браузере:

- приложение: http://localhost:5173;
- документацию API: http://localhost:8000/docs;
- проверку сервера: http://localhost:8000/health — ответ `{"status":"ok"}`.

Для загрузки демонстрационных квартир:

```powershell
docker compose exec backend python -m app.scripts.seed
```

Скрипт добавляет 90 синтетических квартир. Повторный запуск не создаёт дубликаты. Для реальных данных войдите администратором и используйте раздел «Администрирование → Импорт данных».

### Последующие запуски и остановка

```powershell
docker compose up -d
```

Остановка с сохранением базы:

```powershell
docker compose down
```

Не добавляйте к остановке параметр `-v`: он удаляет тома, в которых хранится база. Обычное копирование папки проекта не включает содержимое Docker-томов.

## 3. Вариант B: Windows без Docker, с SQLite

Установите Python 3.12 и Node.js 22 с npm. После установки откройте новое окно PowerShell и проверьте:

```powershell
py -3.12 --version
node --version
npm.cmd --version
```

### Первая подготовка

Из корня перенесённого проекта:

```powershell
cd C:\Projects\Nedvichka
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r backend/requirements.txt
cd frontend
npm.cmd ci
cd ..
```

Для установки зависимостей нужен интернет. Используется `npm.cmd`, поэтому включать выполнение PowerShell-скриптов не требуется.

### Сервер — первое окно PowerShell

```powershell
cd C:\Projects\Nedvichka\backend
Remove-Item Env:DATABASE_URL -ErrorAction SilentlyContinue
..\.venv\Scripts\alembic.exe upgrade head
```

Удаление переменной выше действует только в текущем окне PowerShell и выбирает локальную SQLite-базу. Если вы скопировали `backend/realestate.db`, сохранятся прежние аккаунты, предложения и оценки. Если файла нет, миграция создаст новую базу.

Для создания нового администратора выполните в этом же окне, подставив свои значения:

```powershell
$env:ADMIN_EMAIL = 'ваш-email'
$env:ADMIN_PASSWORD = 'ваш-новый-пароль-минимум-12-символов'
..\.venv\Scripts\python.exe -m app.scripts.bootstrap
Remove-Item Env:ADMIN_PASSWORD
```

В этом режиме корневой `.env` автоматически не читается. Bootstrap не меняет пароль и роль уже существующей учётной записи. Если администратор не нужен или уже перенесён в базе, этот шаг пропустите.

Если нужны демонстрационные квартиры:

```powershell
..\.venv\Scripts\python.exe -m app.scripts.seed
```

Запустите сервер и оставьте окно открытым:

```powershell
..\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

### Интерфейс — второе окно PowerShell

```powershell
cd C:\Projects\Nedvichka\frontend
npm.cmd run dev -- --host 127.0.0.1
```

Оставьте оба окна открытыми. Откройте http://localhost:5173.

Для следующих запусков достаточно снова выполнить команды запуска Uvicorn и Vite в двух окнах. Устанавливать зависимости и запускать seed каждый раз не нужно. После обновления кода выполняйте миграции; если изменились зависимости — повторите установку.

**Остановка:** нажмите `Ctrl+C` в каждом из двух окон. База останется на диске.

## 4. Как проверить работу

1. Зарегистрируйтесь через интерфейс или войдите в перенесённый аккаунт. Подтверждения email нет; пароль обычного пользователя — минимум 10 символов.
2. Если загружены демонстрационные данные, откройте «Экспресс-оценка» и оставьте параметры по умолчанию: Ростов-на-Дону, Центр, 55 м², 2 комнаты, этаж 5 из 9, кирпичный дом, хорошее состояние.
3. Выполните расчёт, откройте историю и скачайте PDF.
4. Для импорта войдите администратором, выберите CSV/XLSX, сначала проверьте файл, затем импортируйте. Шаблон: `sample-data/template.csv`.

Карта OpenStreetMap требует интернет для подложки. Остальные основные функции после установки зависимостей работают локально. Для PDF в Windows используется Arial; Docker-образ устанавливает DejaVu Sans для кириллицы.

## 5. Резервная копия и перенос данных

### Текущая SQLite-база

Остановите оба процесса (`Ctrl+C`), затем скопируйте `backend/realestate.db` в резервную папку. На другом компьютере положите копию в `backend` до запуска сервера. Не заменяйте файл базы при работающем приложении. Исходную копию сохраните до проверки переноса.

Файл `backend/.jwt-secret` переносить необязательно: с новым секретом пользователи просто войдут заново. Пароли аккаунтов хранятся в базе в виде хешей и не меняются от смены JWT-секрета.

### PostgreSQL в Docker

Для резервной копии работающей Docker-базы выполните из корня проекта:

```powershell
docker compose exec db sh -c 'pg_dump -U "$POSTGRES_USER" -d "$POSTGRES_DB" -Fc -f /tmp/realestate.dump'
$dbContainer = docker compose ps -q db
docker cp "${dbContainer}:/tmp/realestate.dump" .\realestate.dump
```

Перенесите `realestate.dump` вместе с проектом. Для восстановления используйте новую пустую базу на другом компьютере. Сначала запустите только PostgreSQL, затем восстановите копию и запустите приложение:

```powershell
docker compose up -d db
docker compose ps
$dbContainer = docker compose ps -q db
docker cp .\realestate.dump "${dbContainer}:/tmp/realestate.dump"
docker compose exec db sh -c 'pg_restore -U "$POSTGRES_USER" -d "$POSTGRES_DB" --no-owner --no-privileges --exit-on-error /tmp/realestate.dump'
docker compose up -d --build
```

Дождитесь статуса `healthy` у базы перед восстановлением. Не запускайте backend до восстановления: он создаёт схему в пустой базе. Восстановление предназначено для новой базы; для базы с существующими таблицами сначала подготовьте отдельное место восстановления. Дамп содержит аккаунты и историю — храните его как закрытую резервную копию.

## 6. Если не запускается

| Проблема | Что сделать |
| --- | --- |
| Docker не найден | Установить и запустить Docker Desktop либо выбрать вариант без Docker. |
| Cannot connect to Docker daemon | Дождаться запуска Docker Desktop и проверить режим Linux-контейнеров. |
| `py -3.12` не найден | Установить Python 3.12 с Python Launcher, открыть новое окно PowerShell. |
| `npm.cmd` не найден | Установить Node.js 22, открыть новое окно PowerShell. |
| Ошибка загрузки пакетов | Проверить доступ к интернету и повторить `pip install` / `npm.cmd ci`. |
| Порт 8000 или 5173 занят | Остановить ранее запущенную копию приложения и повторить запуск. Не запускать Docker и локальный вариант одновременно на этих портах. |
| Vite открыл порт 5174 | Освободить 5173 и перезапустить: CORS настроен на 5173. |
| Интерфейс есть, но данные не загружаются | Проверить http://localhost:8000/health и журналы backend. Использовать адрес `localhost:5173`, а не IP другого компьютера. |
| Не получается войти после переноса | Убедиться, что перенесена нужная база. Новая Docker-база не содержит аккаунты из SQLite. |
| Нет административной панели | Войти аккаунтом администратора, созданным через bootstrap. Обычная регистрация не даёт права администратора. |
| Недостаточно аналогов | Загрузить seed или минимум три актуальных подходящих предложения; проверить город, район, комнаты и площадь. |

Журналы Docker:

```powershell
docker compose logs --tail=100 backend
docker compose logs --tail=100 frontend
docker compose logs --tail=100 db
```

Каждый компьютер запускает собственную независимую копию. Адрес `localhost` всегда относится к тому компьютеру, на котором открыт браузер. Эта инструкция не включает настройку общего сервера для нескольких компьютеров.

Docker/восстановление PostgreSQL описаны по конфигурации проекта, но не проверялись на текущем компьютере: Docker здесь отсутствует. Запуск без Docker, API-тесты и сборка интерфейса ранее проверены.

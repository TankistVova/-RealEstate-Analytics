# RealEstate Analytics

Для переноса проекта и данных используйте [пошаговую инструкцию запуска на другом компьютере](ЗАПУСК-НА-ДРУГОМ-КОМПЬЮТЕРЕ.md). В ней описаны Docker, Windows без Docker, создание администратора, резервные копии и остановка.

Локальная информационно-аналитическая система экспресс-оценки квартир вторичного рынка. React + TypeScript + Vite, Tailwind CSS, React Router, TanStack Query, Recharts, React Leaflet; FastAPI, SQLAlchemy 2, Alembic, PostgreSQL, Argon2, JWT, Pandas/openpyxl и ReportLab.

Расчёт выполняется на сервере сравнительным методом. ML, нейросети, платные API и внешние AI-сервисы не используются. Все показатели интерфейса поступают из API и вычисляются по текущей базе. Синтетические записи явно обозначаются.

## Запуск через Docker

Нужен Docker Desktop с Compose и Linux-контейнерами. Из корня проекта:

```powershell
docker compose up --build
```

Доступны:

- Интерфейс: http://localhost:5173
- API: http://localhost:8000
- Swagger: http://localhost:8000/docs

Compose ожидает готовность PostgreSQL, применяет миграции Alembic, создаёт настройки и запускает backend и frontend. При первом запуске база предложений пустая. Регистрация пользователя доступна сразу. Секрет JWT при отсутствии переменной автоматически генерируется и хранится в томе `backend_state`, а не в исходниках.

При первом запуске Docker загружает образы и зависимости из интернета. После сборки основные функции работают локально; подложка карты OpenStreetMap требует интернет. Без подложки база, расчёт, история, аналитика и PDF продолжают работать.

### Администратор

До запуска скопируйте `.env.example` в `.env` и заполните:

```dotenv
ADMIN_EMAIL=ваш-email
ADMIN_PASSWORD=ваш-новый-пароль
JWT_SECRET=ваша-случайная-строка-длиной-не-менее-32-символов
```

Пароль администратора должен содержать минимум 12 символов. Для обычной регистрации требуется минимум 10. Готовых административных паролей в проекте нет. Не добавляйте `.env` в репозиторий. Можно также изменить локальные реквизиты PostgreSQL до первого запуска; в URL пароль должен быть URL-совместимым.

При изменении `.env` примените конфигурацию:

```powershell
docker compose up -d --force-recreate backend
```

Bootstrap создаёт нового администратора только при отсутствии указанного email. Он не повышает права существующей обычной учётной записи и не меняет существующие пароли. Используйте отдельный новый email администратора. Для явного выполнения bootstrap:

```powershell
docker compose exec backend python -m app.scripts.bootstrap
```

### Демонстрационные данные

```powershell
docker compose exec backend python -m app.scripts.seed
```

Скрипт добавляет 90 **синтетических демонстрационных** квартир Ростова-на-Дону в районах Центр, Западный и Северный. Даты рассчитываются относительно запуска. Повторный запуск не добавляет дубликаты и не обновляет существующие записи. Если спустя 180 дней записи устарели, удалите демонстрационные объекты через администратора и запустите seed заново либо импортируйте актуальную базу.

Для демонстрации:

1. Зарегистрируйтесь и войдите в интерфейс.
2. Откройте «Экспресс-оценка».
3. Укажите Ростов-на-Дону, Центр, 55 м², 2 комнаты, этаж 5 из 9, кирпичный дом, хорошее состояние. Эти параметры заполнены по умолчанию.
4. Нажмите «Рассчитать стоимость». Результат автоматически сохраняется вместе с аналогами и настройками.
5. Изучите поправки и веса, скачайте PDF, откройте «Мои оценки».
6. Посмотрите аналитику и карту. Демонстрационный результат не является оценкой текущего рынка.

### Импорт собственных предложений

Войдите как администратор, откройте «Администрирование → Импорт данных», выберите CSV в UTF-8 или XLSX. Сначала нажмите «Проверить файл», изучите ошибки, затем «Импортировать проверенный файл». Проверка не записывает данные. При импорте корректные строки загружаются, ошибки отдельных строк не отменяют остальные строки. Повторная проверка выполняется и при фактическом импорте.

Шаблон заголовков находится в `sample-data/template.csv`. Обязательные поля:

```text
city,district,rooms,total_area,floor,floors_total,building_type,condition,price_rub,listing_date
```

Необязательные поля: `address`, `year_built`, `latitude`, `longitude`, `kitchen_area`, `source_name`, `source_url`, `external_id`, `status`. Отсутствующие необязательные поля становятся NULL. Даты — `YYYY-MM-DD`; статус по умолчанию `active`. Широта и долгота указываются вместе либо обе отсутствуют. Объекты без координат участвуют в оценке, но не показываются на карте.

Типы дома: `panel`, `brick`, `monolith`, `other`; ремонт: `needs_repair`, `normal`, `good`, `excellent`. Принимаются также русские названия из интерфейса. CSV поддерживает запятую и точку с запятой как разделители, числа могут иметь десятичную запятую в корректно оформленном CSV.

## Методика

1. Активные объявления того же города не старше 180 дней. Этап 1: тот же район и комнаты, площадь ±25%. Если аналогов меньше трёх — этап 2: любой район, те же комнаты, ±30%. Этап 3: любой район, комнаты ±1, площадь ±35%.
2. При наличии минимум пяти кандидатов выполняется фильтрация ценовых выбросов по IQR цены за м². После неё требуется минимум три аналога. При необходимости поиск продолжает расширяться.
3. Схожесть: площадь 50%, район 25%, комнаты 15%, категория этажа 10%. Площадь: `max(0, 1 - |S_target - S_analog| / (0.35 × S_target))`. Район: 1 или 0.4; комнаты: 1, 0.5 или 0; этаж: 1 или 0.6. Первый этаж имеет приоритет в одноэтажном здании.
4. Выбираются до 10 наиболее схожих кандидатов; при равенстве предпочтение отдаётся более свежим. Цена не участвует в ранжировании по схожести.
5. Цена за м² корректируется отношением коэффициентов целевого объекта к аналогу: ремонт × тип дома × категория этажа. Совокупная поправка ограничивается диапазоном 0.80–1.25.
6. Вес аналога = квадрат схожести / сумма квадратов схожести. Взвешенная цена за м² умножается на площадь. Общая стоимость округляется до ближайшей тысячи, половина — вверх.
7. Диапазон по умолчанию ±10% — условный ориентир, не статистический доверительный интервал. Если нет трёх подходящих аналогов, API возвращает HTTP 422 без выдуманной стоимости.

Стартовые коэффициенты демонстрационные. Администратор может менять ремонт, тип дома, этаж, пределы поправки, процент диапазона, допуски площади, срок актуальности и максимум аналогов. Старые оценки содержат полный JSON-снимок входных данных, результата и настроек; изменение или удаление объявлений не пересчитывает историю.

## Структура

```text
backend/app/api/          REST API, фильтры, права доступа
backend/app/core/         JWT и Argon2
backend/app/db/           подключение SQLAlchemy
backend/app/models/       модели и индексы
backend/app/schemas/      Pydantic-валидация
backend/app/services/     аналоги, оценка, аналитика, импорт, PDF
backend/app/scripts/      bootstrap администратора и seed
backend/alembic/          миграция схемы
backend/tests/            тесты pytest
frontend/src/api/         HTTP-клиент и загрузка PDF
frontend/src/components/  формы, фильтры, общие элементы
frontend/src/pages/       страницы приложения
frontend/src/types/       TypeScript-типы
sample-data/              шаблон импорта
```

Все REST-маршруты имеют префикс `/api/v1`, кроме `/health`. Swagger содержит схемы, параметры фильтрации и форматы ответов. Основные коллекции объектов и оценок имеют пагинацию. Для карты загружается до 200 предложений на страницу; доступны переключатели страниц. Карта первоначально центрирована на Ростове-на-Дону; другие города можно найти перемещением карты.

Безопасность: Argon2-хеши паролей, JWT на 8 часов, проверка роли и владельца на backend, серверная валидация, ORM, ограничение файлов, CORS на localhost:5173. JWT хранится в sessionStorage вкладки и очищается при выходе/истечении авторизации. Порты Docker привязаны к 127.0.0.1. Приложение рассчитано на локальную работу; для публичной эксплуатации потребуются отдельные настройки HTTPS, защиты входа и инфраструктуры.

## Проверки

В контейнере (тесты исключены из рабочего образа; примонтируйте каталог):

```powershell
docker compose run --rm -v ./backend/tests:/app/tests -v ./backend/pytest.ini:/app/pytest.ini backend python -m pytest -q
```

Или локально, Python 3.12+ и Node.js 22:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r backend/requirements.txt
cd backend
..\.venv\Scripts\python.exe -m pytest -q
cd ../frontend
npm.cmd ci
npm.cmd run build
```

Тесты используют изолированную временную SQLite-базу; PostgreSQL используется в Docker. Проверяются формулы, поправки, нормализация весов, взвешенное среднее, расширение поиска, IQR, недостаток данных, Pydantic-валидация, CSV/XLSX, дубликаты, предварительная проверка, лимит файлов, права, история, снимки, CRUD, фильтры и PDF.

Фактически в окружении разработки: 25 тестов прошли; сборка TypeScript/Vite успешна; npm audit после обновления зависимостей — 0 уязвимостей. Сгенерированный PDF отрисован и проверен, кириллица корректна. Локальные HTTP-проверки backend `/health` и frontend дали 200. Docker в окружении отсутствует, поэтому Compose и PostgreSQL здесь не запускались. Визуальная проверка браузера была остановлена пользователем клавишей Escape; полный сценарий через UI не подтверждён. API-сценарии проверены автоматически.

Дополнительно пройден сквозной smoke-сценарий на запущенном API и базе из 90 демонстрационных квартир. Повторить после seed:

```powershell
docker compose exec backend python -m app.scripts.smoke
```

Smoke создаёт отдельного обычного пользователя со случайным паролем, проверяет регистрацию, вход, оценку с параметрами по умолчанию, предупреждение о синтетических данных, историю, PDF, аналитику, координаты и запрет административных действий. Созданную оценку удаляет; тестовая учётная запись остаётся в базе. Данные для входа не выводятся и не сохраняются в исходниках.

## Локальная разработка без Docker

Для разработки можно использовать локальный PostgreSQL через `DATABASE_URL`. Без этой переменной используется SQLite-файл `backend/realestate.db`; это вспомогательный режим для разработки, основной стек Compose — PostgreSQL.

```powershell
cd backend
..\.venv\Scripts\alembic.exe upgrade head
..\.venv\Scripts\python.exe -m app.scripts.bootstrap
..\.venv\Scripts\python.exe -m app.scripts.seed
..\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

В отдельном терминале:

```powershell
cd frontend
npm.cmd ci
npm.cmd run dev -- --host 127.0.0.1
```

Frontend обращается к `http://localhost:8000/api/v1`. При необходимости укажите `VITE_API_URL` в `frontend/.env` и перезапустите Vite. Bootstrap в этом режиме читает переменные окружения процесса; корневой `.env` автоматически читает только Docker Compose.

Для остановки Docker без удаления базы:

```powershell
docker compose down
```

Том PostgreSQL сохраняет данные между запусками. Не удаляйте том, если хотите сохранить базу и историю.
